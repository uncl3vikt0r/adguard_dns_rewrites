# Smart DNS → AdGuard Desktop

Проект автоматически собирает rewrite-правила Smart DNS-провайдеров в DNS-фильтр AdGuard Desktop. Источниками служат hosts-файлы. Раннер обрабатывает их по приоритету и дополняет основной GeoHide доменами из Malw, Bezmezhau и других списков. Если один домен встречается в нескольких файлах, сохраняется IP из первого источника, где этот домен найден.

## Как это устроено

1. GitHub Actions запускает `runner.py` ежедневно или вручную.
2. Раннер загружает файлы в порядке приоритета: GeoHide → Malw → Bezmezhau → WL DNS → Combined.
3. Если источник недоступен, раннер пишет предупреждение и продолжает. Правила из доступных источников объединяются, дубли разрешаются в пользу источника с более высоким приоритетом.
4. Hosts-строки преобразуются в `$dnsrewrite`, файл записывается в `public/adguard-dns-rewrites.txt` и коммитится только при изменении.
5. AdGuard Desktop загружает опубликованный файл как пользовательский DNS-фильтр.

Порядок можно изменить в `RULE_SOURCES` в начале `runner.py`.


## Подключение в AdGuard Desktop

В AdGuard for Windows откройте **Настройки → DNS-защита → DNS-фильтры** (названия могут отличаться по версии), добавьте пользовательский фильтр по URL `.txt`, включите его и обновите. Проверьте, что домен из списка возвращает IP, указанный в правиле.

Правила используют синтаксис AdGuard `$dnsrewrite`. Поддержку таких правил в удалённой подписке проверьте на установленной версии AdGuard Desktop.

## Источники и fallback

Сейчас подключены следующие автоматически обновляемые hosts-файлы из RussiaFancyLists:

1. GeoHide
2. Malw
3. Bezmezhau
4. WL DNS
5. Combined

Здесь используются именно hosts-списки с IP и доменами, а не DoH URL формата `/dns-query`. DNS-серверы MagicDNS и Bezmezhau из DnsConfUI относятся к DNS-донорам; чтобы получить готовые списки провайдеров, используются опубликованные hosts-артефакты. Если все источники недоступны или не содержат redirect-записей, раннер завершается ошибкой и не записывает пустой фильтр.

## Настройки

| Переменная Actions | Назначение |
|---|---|
| `EXCLUDE_REDIRECT` | Необязательные домены через запятую. Исключаются указанный домен и его поддомены, например `instagram.com,twitch.tv`. |

Блокирующие адреса `0.0.0.0`, `127.0.0.1` и `::1`, а также строки с одним доменом пропускаются. Раннер берёт только redirect-строки.

## Локальный запуск

Нужен Python 3.10 или новее. Сторонние библиотеки не требуются.

```powershell
$env:EXCLUDE_REDIRECT = "instagram.com,twitch.tv"
python .\runner.py
```

Для проверки источников и подсчёта правил без записи файла выполните `python .\runner.py --check`.

## Расписание и диагностика

Workflow запускается ежедневно в 01:30 UTC (04:30 по Москве при UTC+3). Ручной запуск доступен в **Actions → Build AdGuard DNS rewrite filter → Run workflow**. В журнале Actions видны загруженные источники, ошибки и количество уникальных доменов. GitHub может приостанавливать расписание неактивного публичного репозитория — проверяйте вкладку Actions.

## Файлы проекта

- `runner.py` — загрузка, проверка и конвертация hosts-файлов.
- `.github/workflows/build-filter.yml` — расписание и ручной запуск.
- `public/adguard-dns-rewrites.txt` — опубликованный DNS-фильтр.
